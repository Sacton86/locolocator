LocoLocator — Ubiquiti Radio
Provisioning Tool

Step-by-step guide for field technicians using LocoLocator to detect, authenticate, and flash Ubiquiti airOS radios on Linux or Windows.

Versionv1.0.0
PlatformLinux / Windows 10 & 11
RevisedAugust 2026
ClassificationInternal — Technician Use Only
1

Pre-Requisites

Confirm all of the following before running LocoLocator. Do not proceed until every item is satisfied.

  • Laptop Ethernet port available — LocoLocator communicates with the radio over a direct wired connection. Wi-Fi will not work.
  • Ethernet cable connected — Run a cable from the laptop's Ethernet port to the PoE injector's LAN port. The radio plugs into the PoE injector's POE port.
  • Radio powered on and connected — The radio must be plugged into the PoE injector and fully booted before scanning. Allow at least 60 seconds after power-on before starting.
  • Wireless SSID — The network name to assign to the radio pair. Both the Building Side and Sign Side of a pair must share the exact same SSID.
  • Administrator / sudo access — The script must configure network adapters, which requires elevated privileges on both Linux and Windows.
  • Internet access (first run only) — Linux auto-installs sshpass via apt if missing. Windows auto-installs the Posh-SSH PowerShell module if missing. Both require internet on the first run only.
Factory Default vs. Already-Configured Radios LocoLocator handles both. A factory-fresh radio answers at 192.168.1.20 and logs in with ubnt / ubnt. A previously configured radio answers at 192.168.0.218 or 192.168.0.219 and logs in with Admin / !mpact1234. Credentials are selected automatically — no manual entry needed for known IPs.
2

Starting LocoLocator — Linux

Run directly from the internet with a single command, or run the downloaded script. Both require sudo.

  • 1

    Open a terminal and run one of the following:

    Run directly from the internet (no download needed):

    curl -sSL https://raw.githubusercontent.com/Sacton86/locolocator/main/locolocator.sh | sudo bash

    Download first, then run:

    curl -sSL -o locolocator.sh https://raw.githubusercontent.com/Sacton86/locolocator/main/locolocator.sh chmod +x locolocator.sh sudo bash locolocator.sh
  • 2

    The script will display the LocoLocator banner and immediately begin configuring your network adapter. You will see output similar to:

    ==================================================== LocoLocator — Radio Provisioning Tool ==================================================== [*] Detected network interface: eno1 [*] Configuring Ethernet interface (eno1)...

    The interface name (eno1, enp3s0, etc.) will reflect your machine's actual Ethernet port — this is auto-detected.

Missing sshpass If sshpass is not installed, the script will install it automatically via apt. This requires an internet connection and takes 10–20 seconds. It only happens once.
3

Starting LocoLocator — Windows

PowerShell must be opened as Administrator. The script will not run without elevated privileges.

  • 1

    Click the Start button or press the Windows key. Type powershell. Right-click "Windows PowerShell" and select "Run as administrator". Click Yes on the UAC prompt.

    Confirm the title bar reads "Administrator: Windows PowerShell" before continuing.

  • 2

    Run one of the following commands:

    Run directly from the internet:

    Invoke-Expression (Invoke-WebRequest -Uri "https://raw.githubusercontent.com/Sacton86/locolocator/main/locolocator.ps1" -UseBasicParsing).Content

    Download first, then run:

    Invoke-WebRequest -Uri "https://raw.githubusercontent.com/Sacton86/locolocator/main/locolocator.ps1" -OutFile "locolocator.ps1" -UseBasicParsing Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass .\locolocator.ps1
  • 3

    On the first run, the script will install the Posh-SSH PowerShell module automatically. You will see:

    [*] Installing required module 'Posh-SSH'...

    This takes 20–60 seconds and only happens once. Subsequent runs start immediately.

Must Run as Administrator The script adds IP addresses to your network adapter, which requires admin rights. If you see a red error about permissions, close PowerShell and reopen it using "Run as administrator" as described in Step 1.
4

Radio Detection

Once started, LocoLocator automatically scans for a connected radio at the three known IP addresses. No action is needed if the radio is detected.

  • 1

    The script scans 192.168.1.20, 192.168.0.218, and 192.168.0.219 in order. When a radio is found, you will see:

    [+] Radio detected at: 192.168.1.20
  • 2

    A 15-second countdown begins immediately after detection. This allows the radio to fully boot and stabilize its SSH service before the connection attempt. Do not unplug the radio during this countdown.

    [*] Waiting for device to boot and connect [15s remaining]
Radio Not Detected? If the scan fails, a menu appears with three options — see Section 5 below. The most common cause is the radio still booting. Wait 30 seconds and choose Try Again.
5

If the Radio Is Not Found

If no radio responds to the scan, LocoLocator displays a recovery menu instead of exiting. You will see:

[!] No radio detected at 192.168.1.20, 192.168.0.218, or 192.168.0.219. 1) Try Again 2) Enter IP Manually 3) Abort Choice:
  • 1

    Try Again (recommended first step) — Enter 1 and press Enter. The script immediately re-scans the same three IPs. Use this if the radio was still booting on the first attempt. You can select Try Again as many times as needed.

  • 2

    Enter IP Manually — Enter 2 and press Enter, then type the radio's IP address when prompted. Use this only if the radio is known to be at a non-standard address (e.g. already configured to a custom IP).

    When you enter a manual IP, LocoLocator will attempt all four known credential combinations before prompting for manual login. Credentials are not auto-selected by IP for manual entries.
  • 3

    Abort — Enter 3 or any other key to exit the script. Use this if the radio appears to be non-responsive or faulty.

Common reasons a radio is not detected:

  • Radio is still booting — wait 30–60 seconds and choose Try Again
  • PoE injector is not powered — check the power brick and indicator light
  • Ethernet cable is plugged into the wrong port on the PoE injector — the laptop goes into the LAN port, not the POE port
  • Cable is faulty — try a different patch cable
  • Radio has a custom IP not in the scan list — use Manual Entry
6

Authentication

After the 15-second boot wait, LocoLocator logs into the radio automatically. Credentials are chosen based on the detected IP — no input is needed for known addresses.

Detected IP Username Password Radio State
192.168.1.20 ubnt ubnt Factory default — never configured
192.168.0.218 Admin !mpact1234 Previously configured as Building Side
192.168.0.219 Admin !mpact1234 Previously configured as Sign Side
Manual IP All four combinations tried; prompts if all fail Unknown / custom

A successful login displays:

[+] Authenticated as 'ubnt'
Authentication Failed If login fails for a manually entered IP, you will be prompted to enter a username and password. If that also fails, the script aborts. Verify the radio is accessible by pinging its IP from a separate terminal window. If you cannot ping it, the physical connection is the issue, not the credentials.
7

Selecting a Role and SSID

After authentication, LocoLocator prompts for the radio's role and the wireless SSID. These two inputs are the only manual entries required during a normal provisioning run.

  • 1

    Select a role. The script will display:

    Select configuration for this unit (192.168.1.20): 1) Building Side (AP / Fallback IP: 192.168.0.218) 2) Sign Side (Station / Fallback IP: 192.168.0.219) Choice [1 or 2]:
    • Building Side (1) — Configures the radio as an Access Point. Installs at the building. Fallback IP will be 192.168.0.218.
    • Sign Side (2) — Configures the radio as a Station (client). Installs at the sign. Fallback IP will be 192.168.0.219.

    Enter 1 or 2 and press Enter.

  • 2

    Enter the SSID. When prompted, type the wireless network name for this radio pair and press Enter. Press Enter without typing anything to use the default Impact.

    Enter Wireless SSID [Default: Impact]:
    The SSID is case-sensitive and must match exactly between the Building Side and Sign Side radios. If you are provisioning a pair, you only enter the SSID once — the second radio inherits it automatically.
8

Configuration Transfer and Reboot

Once the role and SSID are confirmed, LocoLocator handles the rest automatically. No further input is required until the radio finishes rebooting.

  • 1

    The configuration file is generated and transferred to the radio via SSH:

    [*] Generating Building Side config for SSID 'Impact'... [*] Transferring configuration via SSH...
  • 2

    The configuration is written to flash memory and the radio reboots:

    [*] Writing to flash and rebooting radio...
  • 3

    A 15-second countdown runs to allow the radio to complete its reboot cycle. Do not unplug the radio or close the terminal during this period.

    [*] Waiting for radio to reboot successfully [15s remaining]
  • 4

    A success summary confirms the completed configuration:

    ==================================================== [✔] Radio successfully configured and rebooted. SSID: Impact Role: Building Side (AP) — 192.168.0.218 ====================================================
Configuration Complete At this point the radio is fully provisioned. The fallback IP shown in the summary (192.168.0.218 or 192.168.0.219) is what the radio will answer on if it cannot obtain a DHCP address from the network.
9

Provisioning the Paired Radio

After each radio is provisioned, LocoLocator offers to immediately configure its partner — using the same SSID — without restarting the script.

  • 1

    After a Building Side (218) is provisioned, the script asks:

    Provision the paired Sign Side (219) radio now? [y/N]:

    After a Sign Side (219) is provisioned, the script asks:

    Provision the paired Building Side (218) radio now? [y/N]:
  • 2

    Enter y and press Enter to continue, or press Enter alone (or n) to skip.

  • 3

    If you choose yes, the script instructs you to swap the radio:

    [!] Unplug the current radio and connect the Sign Side radio.

    Unplug the PoE cable from the first radio, connect the second radio to the PoE injector, and press Enter when it is powered on and connected.

  • 4

    The paired radio is detected, authenticated, and configured automatically using the same SSID. You will not be prompted for the SSID again — it is inherited from the first radio.

  • 5

    After both radios are done, the script returns to the main loop and asks if you want to configure another independent unit.

Typical Pair Workflow Connect Building Side radio → run script → select role 1 → enter SSID → wait for reboot → answer y to pair prompt → swap to Sign Side radio → press Enter → done. Total time per pair is approximately 3–5 minutes including wait times.
10

Configuring Multiple Units in One Session

After each provisioning job (including any paired radio), LocoLocator asks if you want to start a new independent unit. You do not need to restart the script between jobs.

Configure another radio? [y/N]:
  • 1

    Enter y to start another provisioning job. The script will prompt you to unplug the current radio and connect the next one.

  • 2

    Connect the next radio, press Enter, and the full provisioning sequence repeats from the scan step — including the SSID prompt, so a different SSID can be used for each new job.

  • 3

    Enter n or press Enter alone when finished. The session ends cleanly:

    [*] LocoLocator session complete. Goodbye!
11

Troubleshooting Common Issues

Symptom / Error Cause & Resolution
Radio not detected on first scan The radio is likely still booting. Choose 1) Try Again after waiting 30–60 seconds. If repeated scans fail, verify the PoE injector is powered, the cable is in the correct port (laptop → LAN, radio → POE), and the cable itself is not faulty.
Authentication failed For a manually entered IP, all four standard credential combinations were tried and failed. Confirm the radio's username and password, then enter them manually when prompted. If you cannot log in at all, the radio may need a factory reset (hold the reset button for 10 seconds until the LED flashes).
Could not detect an active Ethernet interface (Linux) No interface starting with eth or en was found in an up state. Run ip link show to list interfaces. If your Ethernet port is down, connect the cable first — the interface must be physically active to be detected. If the interface has an unusual name, edit the IFACE detection line in the script.
Could not detect an active Ethernet adapter (Windows) No adapter with Status "Up" matching Ethernet naming conventions was found. Open Device Manager and confirm the Ethernet adapter is enabled and has a driver installed. A USB-to-Ethernet adapter may use a non-standard name — check Get-NetAdapter in PowerShell to see all adapters.
Posh-SSH install fails (Windows) The machine may not have access to the PowerShell Gallery, or TLS 1.2 is not enabled. Run the following two commands in an Admin PowerShell and then re-run the script:

[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
Install-Module -Name Posh-SSH -Force -Scope CurrentUser
Both radios configured but they won't link Verify both radios were given the exact same SSID — including capitalization. If you used the paired-radio follow-up workflow, SSIDs match automatically. If you ran two separate sessions and typed the SSID manually each time, a typo will prevent the link. Re-provision one radio using the correct SSID to fix it.
Script exits immediately on Linux with "permission denied" The script was not run with sudo. Re-run it as: sudo bash locolocator.sh. Running with ./locolocator.sh alone will fail if you are not already root.

Provisioning Flow at a Glance

  • Connect radio to PoE injector → connect laptop to PoE injector LAN port
  • Run LocoLocator with sudo / as Administrator
  • Wait for radio detection and 15-second boot countdown
  • Select role: 1 = Building Side, 2 = Sign Side
  • Enter SSID (or press Enter for default Impact)
  • Wait for config transfer and 15-second reboot countdown
  • Answer y to provision the paired radio, or n to skip
  • Repeat for additional pairs as needed, then exit with n
